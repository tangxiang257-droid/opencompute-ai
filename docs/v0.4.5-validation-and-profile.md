# OpenCompute AI v0.4.5 — Qwen2 数值独立性和通信基准测试

## 本轮的可核验目标

验证平台是否能正确拆分模型计算，同时为“内存聚合”和“推理加速”建立**不同的验收指标**。保留 GPT-2、Qwen2 v1/v2、之前的安全校验、双 Worker HTTP/Gloo 兼容性；不新增云资源，不下载 DeepSeek 官方模型，也不支持陌生公网节点。

### 新增模块

- `compute/qwen2_trace.py`：**显式可选**的 Gloo 每 Rank 通信计时，包括 All-Reduce 次数、本地张量参数字节数、广播次数与耗时。通信时间包括等待同步；`all_reduce_tensor_bytes` **不是线路实际传输字节数**。
- `compute/qwen2_generate.py --profile`：在生成阶段记录每 Rank 的 preflight、prefill、decode、collective wall time，Linux 当前进程的峰值 RSS（`ru_maxrss`），及完成时的 RSS 样本。常规运行默认不启用 profile。
- `compute/qwen2_validation.py`：逐 Token 比较全词表 logits、greedy 结果、绝对误差、相对误差与 top-2 margin；即使 logits 整体在容差内，生成 Token 不一致也必须标记失败。拒绝非有限浮点、缺失输出和不一致的报告。
- `benchmarks/qwen2_matrix_v045.py`：随机合成权重下，1/2 Gloo Rank × FP32/BF16 存储的重复可运行性能矩阵，含可选保存 JSON。此脚本本身执行**单次**测量，不会假装是多轮统计。
- `tests/test_qwen2_validation_v045.py`：验证错误案例、记录真实性和真实 torchrun 结果的 FP32/BF16 稠密参考一致性。
- `tests/test_qwen2_hf_tiny_v045.py`：独立 Hugging Face **Qwen2ForCausalLM** 对照。这个模型通过代码在内存中随机初始化，不读取模型网站或下载权重；分别验证 1/2 Gloo Rank 和 FP32/BF16 盘上权重。
- `benchmarks/qwen2_offline_validation.py`：加强真实模型验证前的结构一致性条件（RoPE theta、RMS eps、绑权重选项等）、可选本地 chat template 和 SHA-256 原始文件哈希。真实 HF 全模型对照仍须显式 `--compare-run`。
- `tests/test_qwen2_provenance_v045.py`：合成模型校验流程，重点覆盖错误模型结构及早拒绝。

## 一次本机 CI 合成模型结果（2026-11-10）

来源：GitHub Actions `v0.3 heterogeneous CPU cluster` 运行
https://github.com/tangxiang257-droid/opencompute-ai/actions/runs/42780285337

基准使用 `hidden=24`、`num_attention_heads=6`、`num_key_value_heads=2`、`layers=2`、`vocab=64`、`new_tokens=2` 的随机参数模型。测试前的 Gloo 建联和导出不计入推理 Token/s；下面是**一次** CI 主机测量，精度和排名不可推广。

| 磁盘格式 | Rank 数 | 存储的权重文件合计字节 | Rank 0 Token/s | 相对同精度 1 Rank | 最慢 Rank 通信计时占比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32 | 1 | 55,656 | 370.102 | 1.000 | 8.9% |
| FP32 | 2 | 57,592 | 220.817 | 0.596 | 42.9% |
| BF16 | 1 | 29,144 | 363.083 | 1.000 | 8.9% |
| BF16 | 2 | 30,936 | 222.230 | 0.612 | 43.8% |

结论：**协同推理正确 ≠ 协同推理加速。** 在这个极小的合成模型上，计算量不足以摊薄 Gloo 额外同步、权重读取和运行等待时间，所以 2 Rank 更慢。BF16 主要节省文件空间，计算时依然转成 FP32，不得据此声称 BF16 直接提速。单机 Gloo 结果不是跨公网设备性能的估计。

### 指标定义和限制

- `rank0_decode_seconds`：从实际生成开始到完成的 Rank 0 本地墙钟时间，排除初始 Gloo 建联和模型预检查；包含 prompt prefill。
- `tokens_per_second_rank0`：生成 Token 数 / `rank0_decode_seconds`。
- `profile.ranks[].collective_fraction`：该 Rank 的 Gloo All-Reduce/广播**函数内计时** / 该 Rank 解码墙钟时间。包含等候其他 Rank 的时间，不等于网络链路使用率。
- `all_reduce_tensor_bytes`：Rank 本地参与 All-Reduce 的逻辑张量字节总和；不能作为网卡吞吐或通信压缩率的证据。
- `peak_rss_bytes_linux`：Linux 运行时当前 Rank 进程的历史峰值 RSS，不包含邻接 Worker、模型文件复制/缓存或 GPU 内存，也不代表整台机器的峰值内存。macOS/Windows 未提供该字段的等价采样。
- `stored_weight_bytes`：所有 Rank 分块文件总和，不等于按节点实际驻留的 RAM，更不等于原始模型训练体积。
- `speedup_vs_same_dtype_one_rank`：同一工作负载、同一种存储精度下，一个 Rank 的**单次**耗时除以多个 Rank 的**单次**耗时。后续需重复多次、分离预热、报告统计区间。

## 复现方式

```bash
# 保持项目原有 CPU PyTorch 和 requirements-dev.txt 环境
python -m unittest discover -s tests -p 'test_qwen2_validation_v045.py' -v

# 输出摘要 + 新建详细 JSON 报告
OMP_NUM_THREADS=1 python -m benchmarks.qwen2_matrix_v045 \
  --workers 1,2 --precisions float32,bfloat16 --new-tokens 2 \
  --output ./qwen2-v045-matrix.json

# 离线结构/Tokenizer 检查，只读取预先放在本机的可信文件
python -m benchmarks.qwen2_offline_validation \
  --model-dir /trusted/local/qwen2 \
  --tp-shards /trusted/local/qwen2-tp-v2 \
  --prompt '你好' --workers 2 --chat
```

CI 另外使用 `transformers==4.57.1`（仅作为软件测试依赖，**不下载官方模型权重**）创建一个随机初始化的 Qwen2ForCausalLM，对照 TP 数值。为防止自动 skip 错误而假阳性，集群 CI 设置 `OPENCOMPUTE_REQUIRE_HF_TINY=1`、`HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`。若模型类或测试无法执行，应直接失败，不能标记为通过。

## 真正 DeepSeek 预训练模型的后续验收门槛

在获得经审核、合法下载、指定 revision 的官方 Safetensors 和 Tokenizer 后，先在离线环境检查文件及固定摘要：

```bash
python -m benchmarks.qwen2_offline_validation \
  --model-dir /trusted/local/deepseek-r1-qwen \
  --tp-shards /trusted/local/deepseek-tp-v2 \
  --prompt '你好，请简单介绍一下自己' --chat --workers 2 \
  --fingerprint-weights
```

只有在设备 RAM 与磁盘容量充足，且用户同意实际运行完整模型后，才执行：

```bash
python -m benchmarks.qwen2_offline_validation \
  --model-dir /trusted/local/deepseek-r1-qwen \
  --tp-shards /trusted/local/deepseek-tp-v2 \
  --prompt '你好，请简单介绍一下自己' --chat --workers 2 \
  --compare-run --atol 0.04 --rtol 0.02
```

*注意：这只是示例命令，不表示本轮已执行过真实模型对照。* 真正的 HF FP32 参考模型可能需要很多 GB 内存和较长运行时间。不能在资源未知的 GitHub 免费 Runner 上擅自进行大模型全量验证。

下阶段性能优化应补充 3–5 次重复测量、峰值资源监视、不同模型维度下的通信敏感性，以及流水线并行 vs 张量并行的可行性分析。

## 当前仍不支持

- 官方 DeepSeek-R1-Distill-Qwen-1.5B 完整预训练权重的实测成功；
- 真实跨物理设备 GPU 或互联网联合推理；
- 未知计算节点的安全身份、机密隔离和恶意计算结果核验；
- 不同模型架构的即插即用推理，尤其是 Llama、DeepSeek MoE 的未实现引擎。

开发中的 CI 应在对应 commit 运行实际完成后才能声称通过；初始部分成功记录不能替代最新提交的独立 HF 架构验收。
