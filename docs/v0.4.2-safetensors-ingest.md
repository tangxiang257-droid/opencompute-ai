# OpenCompute AI v0.4.2 — 官方 Qwen2/DeepSeek Safetensors 安全导入与容量预检查

## 本阶段的真实能力和边界

本阶段没有下载或运行 DeepSeek 的完整官方权重；新增的是一个**可以读取本地 Safetensors 模型配置、检查权重、计算容量并在当前限制允许时实际转换**的安全导入入口。

支持输入：
- 本地管理员提供的 `config.json` + 单个 `model.safetensors`；
- 本地 `config.json` + `model.safetensors.index.json` + 指数列出的多个 `*.safetensors` 文件；
- 仅 `config.json` 的容量预检查（无需下载任何大模型权重）。

实现文件：`compute/qwen2_safetensors.py`。在 **本地可信目录** 中，逐文件检查文件名、软链接、文件长度、Safetensors 张量名字、形状、数据类型，以及分片索引与真实内容的逐项对应；不执行远端 Python 代码、不加载 `.bin`/pickle、不自动联网。

可选 `--expected-sha256` 让管理员将**单文件** Safetensors 与事先独立确认的 64 位 SHA-256 固定值比较；这仅证明内容指纹匹配，不是模型本身的安全或来源背书。多文件索引目前不支持逐文件受信任摘要表。

### 原有命令的安全变化

`python -m compute.qwen2_shards --model LOCAL_DIR --output OUTPUT` 现在也经过相同的 Safetensors 本地导入器，不再通过 `AutoModelForCausalLM.from_pretrained` 实例化整个原始模型或可能回退加载 `.bin` 权重。随机权重的 `--synthetic` 方式保持不变。

## 用官方 DeepSeek-R1-Distill-Qwen-1.5B 配置做计划

官方配置（固定版本示例）：
https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B/blob/530ca3e1ad39d440e182c2e4317aa40f012512fa/config.json

权重文件信息（另一个官方版本示例，请核对实际下载版本的 SHA）：
https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B/blob/e93784059177e379b713658b88145e0028fac5c1/model.safetensors

已发布的文件大小约 **3.55 GB**、SHA-256 为：

```
58858233513d76b8703e72eed6ce16807b523328188e13329257fb9594462945
```

这些公开信息只是**下载版本校验参照**；当模型仓库出现新版时，需要独立固定所使用的 revision 和文件 SHA，不要盲目复用旧指纹。

官方结构的关键参数：`hidden_size=1536`、`num_attention_heads=12`、`num_key_value_heads=2`、`num_hidden_layers=28`、`vocab_size=151936`、`intermediate_size=8960`，并且不启用滑动窗口注意力。

只保存一份可信的 `config.json` 到本地之后就能估算，无需模型权重：

```bash
python -m compute.qwen2_safetensors \
  --config /your/local/deepseek-qwen/config.json --workers 2
```

按目前将原始权重转换为 **float32** 的输出方式，Rank 0 的词向量矩阵与 LM head 合并写入 `rank0_io.pt`，仅两份矩阵的预计体积约为 **1.87 GB**，超过目前每个分片文件 **512 MB** 的安全上限。这份配置会返回：

```json
{
  "plan": {
    "exportable_under_current_limit": false,
    "reason": "rank0_io.pt or a rank_N.pt is projected to exceed the 512 MB file limit; requires chunked IO and memory-aware loading"
  }
}
```

这是一项**明确拒绝过大的导出**的正确行为，不是证明 DeepSeek 与 Qwen2 架构不兼容。大型真实权重仍然需要下一阶段实现多个 IO 文件和逐层分片，才能进入实际运行验证。

## 小型真实 Qwen2 Safetensors 的离线转换

当手头有符合当前大小上限的、可信的小型模型目录时（包含 config.json 和 Safetensors，不支持其他架构）：

```bash
# 不加载权重张量，只检查文件头与容量
python -m compute.qwen2_safetensors \
  --model-dir /your/local/qwen2 --workers 2

# 单文件可选：固定已核验的权重哈希
python -m compute.qwen2_safetensors \
  --model-dir /your/local/qwen2 --workers 2 \
  --expected-sha256 YOUR_64_CHARACTER_HASH

# 仅容量允许时转换成现有可运行的 Qwen2 TP 分片
python -m compute.qwen2_safetensors \
  --model-dir /your/local/qwen2 --workers 2 \
  --export-to /your/local/exported-qwen2
```

输入输出必须分开，目标文件夹不能已存在，禁止通过提供文件名访问父目录，拒绝软链接权重、索引缺失、额外的未识别模型参数、张量形状不符和不支持的数据类型。

输出必须再次通过 `inspect_bundle` 的 SHA-256 / manifest 校验才能投入后续受信任会话。本阶段导出器虽然会在需要时读取单个 Safetensors 张量，但旧的 Qwen2 exporter 仍将所有目标 Rank 的层权重缓存在内存中，因此**还不是适合超大型模型的常数内存流式转换器**。

## 测试方法与验收要求

开发依赖新增 `safetensors` 与 `numpy`。不需要远端模型：

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p 'test_qwen2_safetensors_v042.py' -v
```

CI 新增的专项测试覆盖：单文件导入、分片索引导入、元数据与文件内容不一致、目录穿越、软链接、张量缺失、多余参数、张量形状错误、SHA-256 错误及 DeepSeek 1.5B 配置超限的预判。

**只有对应提交的 GitHub Actions 检查成功，才标记此阶段的代码测试为通过。** 模型官方权重的实际推理兼容性仍然是未来单独的验收门槛。
