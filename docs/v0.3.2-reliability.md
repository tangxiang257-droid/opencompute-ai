# OpenCompute AI v0.3.2 — reliability and security hardening

**Scope:** This patch hardens the **trusted, single-host research prototype**. It is not public-network security, production cluster orchestration or fault-tolerant large-model serving. This revision does not enable two physical computers to cooperate over Gloo.

## Resolved or mitigated issues

| Concern | v0.3.2 change | Remaining boundary |
|---|---|---|
| Unauthenticated benchmark workload | `/benchmarks` and `/v0.2/plan` require `X-Admin-Key` (fail closed without key); legacy `app/main.py` no longer has a default demo key | No rate limiting or public-facing TLS |
| Ordinary jobs + TP overallocate nodes | `ClusterStore._active_reservations` includes active TP assignments, under the same SQLite write transaction as ordinary task claims | Self-reported resources, no OS-enforced capacity isolation |
| Stale readiness/results | Coordinator expires sessions before ready, shard authorization and completion; late results are rejected | No transparent recovery from a failed collective |
| Hanging peers after cancelled session | Worker uses a supervised subprocess, polls its own assignment while running and terminates its process group when revoked; local maximum run duration retained | Abrupt agent death may still strand children until OS/Gloo timeout |
| Preparation failure stalls group | Worker reports preparation errors; coordinator can fail sessions during `preparing` | Heartbeat loss still uses TTL, and network outages can delay reporting |
| Missing cancellation | Admin-only `POST /v0.3.1/sessions/{id}/cancel` | Cancellation is cooperative and bounded by polling/connection timeout |
| Disk growth | Worker removes per-session shard caches on completion/cancellation; admin-only `POST /v0.3.1/sessions/prune` deletes terminal session DB rows and model files older than a retention threshold | Central cleanup is manual; no background sweeper or shared content-addressed shard cache |
| Result shape abuse | Rank 0 token IDs are checked for vocabulary bounds and count; peers must return matching rank and `completed: true` | **No cryptographic or independent numerical proof** of remote results |
| OOM due to optimistic sizing | TP reservation uses 2x exported shard bytes + 512 MiB runtime allowance; registered worker advertises cgroup-v2-aware RAM when available | Still an estimate; activation peaks, allocator overhead and strict memory sandboxing unverified |
| All CPUs scored equally | TP Worker runs a small local CPU calibration rather than registering a hardcoded `100` score | The score is self-reported, untrusted and cannot compare CPU/GPU meaningfully |

The database migrates existing `tp_assignments` to add `reserved_cpu` and `reserved_memory_mb` columns. Defaults for **older assignments** are 1 core / 512 MiB. Back up the SQLite database before upgrade.

## Administrative operations

Do not publish the API beyond localhost. Create two independent long secrets and keep them out of Git:

```bash
export OPENCOMPUTE_ADMIN_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OPENCOMPUTE_JOIN_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
```

Then start the API with `uvicorn backend.app:app --host 127.0.0.1 --port 8000`.

Inspect an existing session:

```bash
curl -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  http://127.0.0.1:8000/v0.3.1/sessions/SESSION_ID
```

Cancel a preparing/running session:

```bash
curl -X POST -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  http://127.0.0.1:8000/v0.3.1/sessions/SESSION_ID/cancel
```

Remove terminal sessions that have been completed/failed at least 24 hours:

```bash
curl -X POST http://127.0.0.1:8000/v0.3.1/sessions/prune \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"older_than_seconds":86400}'
```

For the earlier CPU benchmark route, also include the admin header:
```bash
curl -X POST http://127.0.0.1:8000/benchmarks \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"workers":2,"hidden":128,"batch":2}'
```

No remote experiments are required for the code-review stage. For optional unit-level regression checks on a trusted local computer:

```bash
python -m unittest discover -s tests -p 'test_tp_v031.py' -v
python -m unittest discover -s tests -p 'test_*_v032.py' -v
python -m unittest discover -s tests -p 'test_cluster_v03.py' -v
```

GitHub CI is configured to run these checks, but a committed test is not equivalent to a confirmed passing run.

## Unresolved / important before public or physical multi-host testing

1. **TCP rendezvous port race:** `_allocate_port()` binds an ephemeral port and releases it before rank 0 starts Gloo. A competing process could claim it. A robust coordinator-owned rendezvous server/socket handoff is still needed.
2. **Single-host only:** `MASTER_ADDR` is fixed to `127.0.0.1`; v0.3.1 TP agents accept localhost only. The existing Docker Compose `worker` is *not* a TP Worker.
3. **Trust model:** shared Join Key + node tokens over localhost do not secure an untrusted internet marketplace. Require TLS/mTLS, scoped credentials, revocation, request quotas, credential rotation and sandboxing.
4. **Model integrity:** SHA-256 validates transfer against the coordinator's file but does not establish that the checkpoint source or remote device is trustworthy. Peer-reported generation results are not independently attested.
5. **Runtime isolation:** worker count / memory reservations are advisory. Add actual cgroup/OS resource enforcement, dynamic RSS checks, and quotas before unattended operation.
6. **Storage/IO bottleneck:** rank zero holds the entire vocabulary IO; weights are duplicated on disk per session and not cached across session identities.
7. **True fault tolerance:** Gloo All-Reduce does not transparently tolerate replacing a failed rank. A failed session must be restarted as a new group from a recoverable checkpoint.
8. **Supply-chain:** trusted model sources, checkpoint validation, pinned dependencies and image auditing are required before public deployment.

**Recommended next engineering gate:** test and audit the new reliability state transitions first, then implement coordinator-owned rendezvous, OS-enforced resource quotas and credential isolation. No cloud VM purchase is required for this phase.
