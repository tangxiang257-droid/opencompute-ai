# OpenCompute AI v0.2 — distributed greedy GPT-2 decoding

The v0.2 CPU prototype performs continuous GPT-2-style autoregressive inference across multiple worker processes. Each worker loads only its rank-local attention/MLP projection shards and keeps its own attention-head KV cache. Rank 0 additionally stores token embeddings, positional embeddings and the tied LM head; activations are broadcast from rank 0. Every Transformer block uses **two Gloo All-Reduce collectives**. This is one-host CPU tensor parallelism, not independent request scheduling.

## 1. Run fully offline with synthetic model weights

From the repository root, on Python 3.11+ with a CPU build of PyTorch installed:

```bash
python -m compute.gpt2_shards --synthetic --output generated/synthetic --workers 2
OMP_NUM_THREADS=1 torchrun --standalone --nproc-per-node=2 -m compute.gpt2_generate \
    --shards generated/synthetic --prompt-ids 1,2,3,4 --max-new-tokens 6
python -m unittest discover -s tests -v
python -m benchmarks.generate --workers 1,2,4 --hidden 32 --heads 4 --layers 2 --new-tokens 8
```

The `generated_ids` are **token IDs, not natural-language text**: the synthetic tensors are not a trained language model. The independent dense reference test checks *every next-token logit*, not just selected greedy IDs. The output records per-rank stored weight bytes, per-rank KV cache bytes, peak process RSS (Linux KiB), elapsed wall time and throughput. On a small local CPU workload, multiple ranks may be **slower** due to communication overhead.

## 2. Import an actual small GPT-2 checkpoint

Install optional [Transformers](https://huggingface.co/docs/transformers) and download a trusted, public GPT-2 architecture model when you have network access:

```bash
python -m pip install "transformers>=4.48,<6"
python -m compute.gpt2_shards --model sshleifer/tiny-gpt2 --output generated/tiny-gpt2 --workers 2
OMP_NUM_THREADS=1 torchrun --standalone --nproc-per-node=2 -m compute.gpt2_generate \
    --shards generated/tiny-gpt2 --prompt-text "Hello, world" --max-new-tokens 12
```

`sshleifer/tiny-gpt2` is an extremely small **real pretrained GPT-2 checkpoint**, suitable for exercising the import pathway, but not for useful natural language responses. The model weights and tokenizer are downloaded by the offline **conversion** step; inference reads only the already exported local shard files and tokenizer. Do not commit downloaded weights to GitHub. Only default GPT-2 `gelu_new` blocks, tied LM head, standard causal attention and divisible head/MLP dimensions are supported.

The exporter *does* hold the complete model while preparing files. **Inference workers do not**; but shared activations, replicated layer norms, Rank-0 embeddings/output projection, and PyTorch runtime overhead remain. The output `weight_bytes_per_rank` counts stored tensors, **not** actual whole-process resident memory. Actual Linux RSS is reported separately.

## 3. What this prototype does not claim

- No real peer-to-peer device discovery, cross-host networking, GPU VRAM pooling, bandwidth shaping, authentication, or sandboxed third-party Worker execution.
- No Llama/DeepSeek architectures, quantization, batch/request scheduling, prompt concurrency, temperature sampling, streaming HTTP interface, or distributed vocabulary head.
- No proof that tensor parallelism will speed up internet-connected personal devices. The network may dominate latency.
- `--report-logits` is for tiny test models only, because it serializes every logit into JSON.

All commands can be run on a PC or free GitHub-hosted CI runner; no purchased server is required.
