# OpenCompute AI v0.6.0：可恢复任务与连接诊断

这是沿用 v0.5.1 服务、数据库和模型引擎的运维升级。新增任务生命周期操作、连接诊断和可选 HTTPS 入口；没有改变真实推理能力的边界。

## 网页变化

- 任务列表支持状态筛选、ID/类型搜索、完整详情、取消及重试。
- 取消 queued/leased 任务会清除租约。已经运行的设备可能继续完成当前 CPU 工作，但过期结果无法提交；通用 Worker 会丢弃 409 结果并继续服务。
- 仅 failed/cancelled 任务可重试；在同一任务 ID 上清零 attempts、结果和错误。重试是新的执行周期，当前没有逐次尝试审计日志。
- 连接错误会保留在页面；可重试、主动断开。断开会清除该标签页密钥及管理数据，旧请求返回后无法重新登录。
- 浏览器禁止 sessionStorage 时仍可在当前页面连接；刷新后需要重输密钥。
- 普通 API 请求等待上限 15 秒；推理请求上限 130 秒，对应默认服务端 120 秒请求超时。停止等待不保证服务端尚未执行，提交失败后应先刷新任务列表，避免重复提交。
- 非本机地址必须使用 HTTPS 才会发送管理员密钥。localhost/127.0.0.1/IPv6 回环仍支持本地 HTTP。
- 模型未配置或服务未运行时停用推理按钮。设备接入命令采用当前网站源地址，支持 POSIX Shell 和 Windows PowerShell，并正确导出和引用环境变量。

## 新增接口

所有新增接口使用 `X-Admin-Key`，继承至少 16 字符的管理员密钥要求。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/v0.3/tasks/{id}` | 完整输入、结果、时间与资源，不含租约令牌 |
| POST | `/v0.3/tasks/{id}/cancel` | 取消 queued/leased；其他状态 409 |
| POST | `/v0.3/tasks/{id}/retry` | failed/cancelled 重新排队；其他状态 409 |
| GET | `/v0.6/system` | API 版本、运行时间、数据库、设备和模型状态 |

未知任务返回 404。`/v0.3/status` 的 counts 增加 `cancelled`，原有四项保持原义。诊断接口返回 200 表示检查已执行；应查看 `state` 和 `database`，不能用它的 HTTP 200 代替就绪判断。`/health` 仍是进程存活检查，版本统一为 0.6.0。

## 更新现有阿里云服务

在现有 `/opt/opencompute-ai` 仓库执行。先查看 `git status`；如有之前为 ECR/Python 镜像源修改的部署文件，保留这些修改并处理冲突，不能用强制重置覆盖。

```bash
cd /opt/opencompute-ai
git status --short
git pull --ff-only
docker compose build
docker compose up -d
python3 scripts/check-deployment.py
```

使用原有 Compose 项目名称和原来的 `.env`，保留 `cluster_data`。不要执行 `docker compose down -v`。构建在现有容器继续运行时完成；最后重建服务会有短暂中断。本次升级不需要主动修改 SQLite 表结构，旧任务和节点仍保留。

镜像现在由 `.dockerignore` 排除 `.env`、本地数据库、Git、虚拟环境和 npm 开发依赖。Compose 为后端增加 `/health` 健康检查，仍仅将 8000 绑定至 127.0.0.1。

## 定位 Funnel / DNS 故障

```bash
# 只检查服务本机
python3 scripts/check-deployment.py --local-only

# 从当前 Tailscale 节点信息读取域名，检查公共 DNS 与 HTTPS
python3 scripts/check-deployment.py

# 已有独立 HTTPS 域名时
python3 scripts/check-deployment.py --url https://你的域名
```

脚本只读，不读取 `.env`，不上传日志，不改 DNS，也不重启服务。退出码 0 为指定范围检查成功；2 为本机异常；3 为公网检查失败或无法进行。`--local-only` 成功不代表公网可达。

系统解析器可能使用 MagicDNS，因此脚本用 `dig` 向公共解析器查询 A/AAAA。缺少 dig 或公共 DNS 请求超时会显示 unknown，不会误报为域名不存在。`funnel_for_current_hostname` 用于识别当前主机名是否配置了 Funnel，但健康检查仍是最终依据。所有结果来自运行脚本的服务器，尚需从独立外部设备验证真实公网访问。

本项目最近截图中的证据是：本机 HTTP 200、Funnel 已启用、公共域名 NXDOMAIN。应先核对当前节点域名和 Funnel 状态，再检查公共 DNS；不能据此更换应用代码、关闭 TLS 校验或持续清空 DNS 缓存。官方此前报告过同类问题，相关事件已标为解决，不能自动认定本实例属于同一故障：

- [Funnel 工作方式与公共 DNS](https://tailscale.com/docs/features/tailscale-funnel)
- [官方 DNS 故障历史](https://statuspage.incident.io/tailscale/incidents/bxbycjcr)

## 可选独立域名 HTTPS 入口

需要一个已经指向服务器公网 IP 的域名，且服务器 80/443 可用。此配置本身不会购买域名或更改阿里云防火墙。已有 Funnel 占用 443 时应先选择要保留的入口，避免端口冲突。

在现有 `.env` 中增加 `OPENCOMPUTE_DOMAIN=你的完整域名`（仅主机名，不带协议/路径），保留原来的两个独立随机密钥：

```bash
docker compose -f compose.yaml -f compose.public.yaml config --quiet
docker compose -f compose.yaml -f compose.public.yaml up --build -d
python3 scripts/check-deployment.py --url https://你的完整域名
```

Caddy 申请并续期 TLS 证书，将网站和带认证的普通 CPU/API 请求转发给后端；限制请求体为 1MB。`/benchmarks`、`/v0.3.1/*` 和 `/v0.4/sessions*` 的研究 Rank/会话操作不通过该公网入口开放，仍在私有接口上使用。公开网页也不包含密钥。该模板增加 TLS 和入口限制，不构成陌生节点、多租户或抗滥用服务；没有限流、用户账号和账单系统。Funnel 不使用此 Caddy 配置，不能自动获得其路径限制。

[Caddy 请求体限制](https://caddyserver.com/docs/caddyfile/directives/request_body) · [反向代理](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

## 验证

```bash
python -m unittest discover -s tests -v
npm --prefix web ci --ignore-scripts
npm --prefix web test
# 可选真实浏览器；在开发机器/CI 安装，不装进生产镜像
python -m pip install playwright
python -m playwright install chromium
python web/tests/browser-smoke.py
```

`Web operations and deployment configuration` CI 验证真实浏览器到 API 到 CPU Worker 的往返，检查取消/重试、重新登录、禁用存储以及 390px 手机视图，并保留桌面/手机截图。它还验证 Compose 合并和 Caddy 配置。原有完整 CPU/Gloo 测试仍单独运行。受限执行环境可能禁止 Unix 套接字或跨进程通信，此时需依据 CI 结果验收，不能声称本机全部通过。

## 保留的实验边界

CPU 通用节点仍只执行三类白名单任务。Qwen2 仍是本机 CPU 双 Rank 实验，每批启动进程组；没有实现远程个人设备 Qwen2、自然语言 Tokenizer、流式生成、GPU 显存聚合或已验证的公网加速。目录收录的 DeepSeek 等模型不因此自动获得执行支持。
