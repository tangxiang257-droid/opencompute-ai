# OpenCompute AI v0.3.3 — owned rendezvous and restart-from-prompt recovery

Status: source changes and offline regression tests have been committed. **GitHub
Actions has not yet been verified as passing.** This remains a **trusted
single-host** CPU-Gloo prototype. No cross-physical-device experiment is
necessary or implied by this release.

## 1. The actual port race and its resolution

Before v0.3.3 the coordinator created a socket on port 0, read the allocated
port, closed the socket, and only later launched rank 0. Any other local
process could claim that port in between.

Now the coordinator starts a real PyTorch `TCPStore` server on
`127.0.0.1:0`. The server obtains an ephemeral port **and remains bound**
throughout the TP session. Managed rank processes set
`OPENCOMPUTE_EXTERNAL_STORE=1` and connect as `TCPStore(is_master=False)`
clients. They call `dist.init_process_group(backend="gloo",
store=client_store, rank=..., world_size=...)`; rank 0 does not attempt to
start a separate competing store.

`torchrun`-managed v0.2 experiments retain their pre-existing `env://`
initialization path when `OPENCOMPUTE_EXTERNAL_STORE` is unset.

The coordinator keeps one strong reference to the TCPStore for each active
session. It releases a completed group's listener after reporting completion,
or a failed group's listener when peers acknowledge stopping or the existing
180-second teardown grace expires.

### Important process architecture constraint

**Run one API process only.** A multi-process Uvicorn deployment (`--workers
2` or more) would create unrelated in-memory coordinator registries, so
separate API workers cannot safely own/recover each other's TCPStore.
The current Compose/Dockerfile uses a single process by default.

When the API process restarts, its prior TCPStore listeners disappear.
During startup the coordinator **marks previous `preparing` and `running`
sessions as failed** rather than incorrectly reporting them as recoverable.
After a coordinator crash, restart from a new session; do not attempt to reuse
the old TCPStore.

## 2. Manual new-group retry (not a KV-cache resume)

Only an administrator may request:

```bash
curl -X POST \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  http://127.0.0.1:8000/v0.3.1/sessions/OLD_SESSION_ID/retry
```

The source session **must be `failed`**. If its ranks are still stopping,
retry returns HTTP 409. After all failed-rank Worker processes acknowledge
teardown, or the 180-second protection period elapses, retry can proceed if
there is sufficient available capacity.

A retry:
1. Reads the old session's immutable *configuration* (workers, prompt tokens
   and generation length).
2. Copies the former session's locally stored rank files to a **new** session
   folder, with bounded filenames/sizes and manifest consistency checks.
3. Selects eligible registered nodes again, atomically reserves capacity and
   establishes a brand-new coordinator-owned TCPStore.
4. Returns a **new** `session_id` and `retry_of`, in `preparing` state.
   Newly assigned agents then download and run their shards normally.

There is **no live-rank replacement**, no reuse of an in-progress Gloo
collective, no restoration of lost KV-cache state, and no exact replay from
the last completed Token. The full original prompt is processed again.

This is a manual, operator-controlled recovery primitive, **not** an automatic
bounded retry policy or complete fault-tolerance solution.

## 3. Offline correctness checks

The new `tests/test_rendezvous_v033.py` tests use a mock TCPStore in the
coordinator: owned-reference lifetime, failed-session retry constraints,
authentication, session restart invalidation and client-store process-group
initialization (mocked). CI also invokes the existing
`benchmarks.tp_session_demo` to exercise a real localhost CPU Gloo group.

```bash
python -m unittest discover -s tests -p 'test_rendezvous_v033.py' -v
python -m unittest discover -s tests -p 'test_tp_v031.py' -v
python -m unittest discover -s tests -p 'test_*_v032.py' -v
```

These are not tests of separate household devices, WAN packet loss or
production recovery. The user has requested **no physical device experiments**.

## 4. Remaining engineering blockers

- TCPStore and Gloo are still localhost-only; no public-network admission or
  private-VPN transport has been implemented.
- Only a single active TP session / API process is supported.
- Control-plane restart deliberately fails in-flight sessions; no durable
  distributed rendezvous or automatic checkpoint-based generation recovery.
- Model files can be altered by a trusted local administrator between sessions.
  SHA-256 verifies transfer integrity, not trust of checkpoint provenance.
- CPU/Memory quotas are advisory, not enforced by isolated cgroups on each
  worker process.
- A 180-second grace is a fail-safe **timeout**, not proof that a crashed
  remote process has stopped.
- Results from an untrusted Worker are not independently verified, and no
  TLS/mTLS/remote reputation or adversarial scheduling protection exists.

**Suggested next gate:** independent CI green status, bounded failure/cancel
test coverage, and strict process isolation before cross-host or public usage.
