# OpenCompute AI v0.4.4 — Offline Tokenizer and Qwen2/DeepSeek reference parity

This is an **opt-in local-only validation contract** for genuine pretrained Qwen2-compatible checkpoints. No official model is downloaded by this feature and CI uses synthetic weights and mocked tokenizers. It is separate from the experimental public-device compute-pool goal.

## Why a second reference matters

The existing `compute.qwen2_reference` uses the same mathematical implementation primitives as our rank-local code, which is useful for checking tensor slicing but not sufficient to certify compatibility with *stock Hugging Face Transformers* execution and tokenization. This tool introduces a separate trusted local reference implementation using `AutoModelForCausalLM` and the actual local tokenizer.

An acceptable real-model result requires *both* generated token IDs and per-step logits to match within a declared precision tolerance. It must never mark a run successful only because both runs produced plausible Chinese text.

## Check the local tokenizer and model metadata without inference

The strict preflight script:
```bash
# Optional (only for locally installed trusted tokenizer and reference tools)
python -m pip install 'transformers>=4.44,<5' tokenizers

python -m benchmarks.qwen2_offline_validation \
  --model-dir /trusted/local/qwen2-model \
  --tp-shards /trusted/local/converted-v2 \
  --prompt '你好，请介绍你自己' --workers 2
```

The default script validates the local Safetensors directory, model architecture dimensions, TP shard manifest, tokenizer IDs and vocabulary/context constraints. It **does not instantiate any full pretrained reference model** and does not run Gloo until `--compare-run` is explicitly supplied.

For tokenizer-only checks, especially when the selected model needs its official chat template, a separate helper offers:

```bash
python -m benchmarks.qwen2_offline_reference \
  --model-dir /trusted/local/qwen2-model \
  --text '你好' --chat --tokenize-only
```

That alternative helper can also perform TP generation without loading the large Hugging Face reference when `--shards` is supplied. The strict preflight tool additionally checks the exported model's dimensions before any reference execution.

## Explicit opt-in full-reference comparison

**Only on a trusted local Linux machine with adequate RAM**, after the source Safetensors and exported v2 files have already been validated and preserved:

```bash
python -m benchmarks.qwen2_offline_validation \
  --model-dir /trusted/local/qwen2-model \
  --tp-shards /trusted/local/converted-v2 \
  --prompt '你好' --workers 2 --max-new-tokens 2 \
  --compare-run --atol 0.04 --rtol 0.02
```

The reference loader always uses `local_files_only=True`, `trust_remote_code=False`, and `use_safetensors=True`. No user-chosen Python module, remote URL or executable is run. Gloo is started via the fixed `compute.qwen2_generate` entry point with `--standalone`, and an explicit timeout.

The HF reference is *FP32* for compatibility comparison. An on-disk BF16 version stores rounded weights and should not be expected to give bit-identical logits. Report a maximum absolute difference, max relative difference, per-step tolerance conclusion and the greedy token IDs; never hide a changed greedy choice behind a permissive tolerance.

**Memory warning:** even a 1.5B-class reference can require multiple gigabytes of memory for full FP32 weights, inference activations, and temporary allocations. Inference is strictly opt-in. This utility does **not** implement an operating-system RAM limit: run only with resource guardrails appropriate to the trusted host.

## Test coverage and what is not certified

```bash
python -m unittest discover -s tests -p 'test_qwen2_offline_validation_v044.py' -v
```

The CI contract tests:
- Local tokenizer options preventing network access and remote custom code
- The HF source loader's Safetensors-only and FP32 flags
- Fixed non-shell Gloo command dispatch and locally required files
- Per-step logit mismatch and changed token detection
- Synthetic local Safetensors + exported chunk preflight without loading HF
- Rejection of source-vs-export model dimension mismatches before expensive operations

The tests mock the Hugging Face model implementation and do **not** certify official DeepSeek model numerical compatibility. That requires separately approved local model files, sufficient RAM and an explicit reference execution. The project also does not claim that an arbitrary remote node or model publisher is safe merely because an official DeepSeek architecture is used.

The primary v0.4.4 BF16/caching implementation is in `compute/qwen2_chunked.py` and is covered by `tests/test_qwen2_bf16_v044.py`; refer to the main project README and Actions status for those code paths.
