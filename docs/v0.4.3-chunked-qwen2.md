# OpenCompute AI v0.4.3 — Qwen2 逐层分片和分块词表存储

## 本轮已实现的内容

之前的 `opencompute-qwen2-tp-v1` 使用 `rank0_io.pt` 保存整个词向量和 LM Head，每个 `rank_N.pt` 保存该 Rank 的所有 Transformer 层。面对 DeepSeek-R1-Distill-Qwen-1.5B 一类较大词表模型，单文件可能大于原有 512,000,000 字节上限，Rank 0 加载峰值也难以控制。

新增实验格式 **`opencompute-qwen2-tp-v2`**，采用：
- `rank0_embed_000.safetensors` 等独立词向量行分块；
- `rank0_head_000.safetensors` 等独立 LM Head 行分块。权重绑定时不重复保存头部权重，推理读取相应词向量块；
- `rank0_norm.safetensors`；
- `rank_0_layer_000.safetensors`、`rank_1_layer_000.safetensors` 等按 Rank / Transformer 层拆分的文件；
- `manifest.json`，记录格式、架构尺寸、Rank 数、词表分块行数等。

所有 v2 权重文件使用 **Safetensors**，每文件仍须满足原有大小限制；单个会话最大 512 文件，词表最多 128 块。原 GPT-2 和 Qwen2 v1 格式仍保持独立兼容，不会自动修改现有检查点。

## 运行时内存设计

- **离线转换**：对于本地 `model.safetensors` 或 `*.safetensors` 索引源，通过 `safe_open.get_slice()` 分行获取 Embedding / Head，其他 Transformer 权重逐层处理，不再缓存所有目标 Rank 的所有层文件。
- **推理计算**：每个 Rank 的层权重按层文件读取；每步生成都会重新读取所需权重文件。Rank 0 仅按 Token 位置读取所需 Embedding 分块，LM Head 的输出使用分块矩阵逐一计算再合并 Logits。
- **安全校验**：manifest 严格限制路径/块数/维度；每个文件通过会话 SQLite 中的大小和 SHA-256 固定值校验；Worker 只能领取自己 Rank 的文件，预检查 Safetensors 张量键名、形状和类型后才进入 Gloo 推理。
- **调度**：v2 的预留内存不再以**全体文件总大小**作为每个节点的单次加载大小，而以层/IO 块的保守临时占用估算。该估算不能替代实际 RSS 监控和 cgroup 限制。

**明确限制：** 这不是可证明恒定 RSS 的引擎。Python/PyTorch 的 CPU 内存分配器、KV Cache、临时激活张量和部分上游层权重仍会占用内存。逐 Token、逐层读盘会大幅增加磁盘 I/O，可能明显降低速度；后续需要模型缓存、BF16 与更细的内存/吞吐规划。

## 不下载大型模型时的离线操作

只用已准备好的可信本地模型文件：

```bash
# 只读取 config.json，估算 v1/v2 文件大小与分块数量
python -m compute.qwen2_safetensors \
    --config /local/model/config.json --workers 2

# 核验 Safetensors 目录的文件名/索引/头部及结构
python -m compute.qwen2_safetensors \
    --model-dir /local/model --workers 2

# 使用新的 v2 分块格式转换：不会覆盖已存在的目标目录
python -m compute.qwen2_safetensors \
    --model-dir /local/model --workers 2 \
    --export-to /local/exported-v2 --chunked

# 如果已从官方发布方单独核实单文件 SHA-256，可另外添加
# --expected-sha256 <64 位小写十六进制摘要>
```

输出目录中的 `manifest.json` 格式为 `opencompute-qwen2-tp-v2`。将**完整导出目录**作为管理员可信检查点放入 `OPENCOMPUTE_TP_CHECKPOINTS` 下后，可以继续通过 `qwen2-local-checkpoint` 模型 ID 申请受控会话。协调器会复制、固定 SHA-256，并给不同 Worker 只分发各自的文件。

原 Qwen2 v1 工具仍可使用，不需要迁移历史检查点。测试脚本使用本地随机权重，永不自动下载 DeepSeek 的大型模型。

## 验收项目

```bash
python -m unittest discover -s tests -p 'test_qwen2_chunked_v043.py' -v
python -m benchmarks.qwen2_chunked_session_demo
```

该专项测试对 v2 的 1 / 2 Rank 随机权重生成结果及每步 Logits 与单进程密集参考实现进行对照，并覆盖：
- 绑定 Embedding 权重时省去重复的 Head 文件；
- 仅分块读取大词表数据的源映射；
- 模型文件清单、跨 Rank 读取权限、SHA-256 篡改和非法 Safetensors 文件头；
- 受信任会话创建与中止后手动重试；
- 从本地小型 Safetensors 文件转为 v2；
- 仅通过配置估算 DeepSeek-R1-Distill-Qwen-1.5B 的 v2 文件可行性。

另一个完整集成脚本在本机起临时 HTTP 服务和两名 Worker，下载各自的 v2 文件，运行 Gloo TP，最后对照单进程结果。**这个测试仍然不是两台真实电脑之间的联机实验。** 是否已通过必须查看具体提交的 GitHub Actions 记录，不能把“测试代码已加入”说成“验收通过”。

## 不能提前宣称支持的功能

- **DeepSeek 官方预训练权重未下载或实跑**。v2 的 DeepSeek 1.5B 容量估算通过，不意味着官方模型数值一致、能按时完成推理或可用于在线产品。
- 目前导出将权重转换为 **float32**，会放大部分 BF16 模型的磁盘容量；需要额外考虑原文件、输出目录、会话复制与 Worker 缓存的总空间。
- 大模型真实性能、高内存压力行为和 Tokenizer 的官方结果一致性尚无测试数据。
- GPU、量化、流水线与 MoE/专家并行不包含在本次版本中。
- Gloo 依然只面向可信本机，绝不能将此版本直接开放给陌生互联网计算节点。

**下一阶段建议：** 先对可信官方 Qwen2/DeepSeek 小型预训练权重完成 BF16/FP32 的 Tokenizer 和逐 Token 数值验收，再基于实际 RAM 与磁盘指标决定缓存和量化策略；不要直接购买服务器进行大模型实验。
