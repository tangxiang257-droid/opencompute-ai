# OpenCompute AI v0.3 — 异构设备算力池（本地原型）

v0.3 将**设备注册 / 心跳 / 资源感知任务调度**接入现有 FastAPI 服务，同时保留 v0.2 CPU GPT-2 张量并行实验。

这两个子系统目前仍然是独立功能：v0.3 分配的是 `sum`、`sha256`、`matmul_checksum` 等明确允许的小任务；**尚不能自动把一个大模型的分片推理分发给注册节点**。这是后续开发阶段的集成目标。

## 1. 本地运行（不买云服务器）

在项目根目录使用 Python 3.11+：

```bash
python -m pip install -r requirements.txt
# 如需 API 自动化测试：python -m pip install 'httpx>=0.27,<1'

# 下面两项必须分别设置为随机长字符串；不要上传 .env 到 GitHub
export OPENCOMPUTE_ADMIN_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OPENCOMPUTE_JOIN_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OPENCOMPUTE_DB_PATH="./.opencompute/cluster.sqlite"

uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

在另一个终端启动一个 CPU Worker（必须从主进程安全地传递 Join Key）：

```bash
export OPENCOMPUTE_JOIN_KEY='<与服务端相同的密钥>'
python -m cluster_v03.worker --url http://127.0.0.1:8000 --name laptop
```

也可以启动第二个 Worker 并设置不同的 `--score` 作为**模拟的性能评分**：

```bash
python -m cluster_v03.worker --url http://127.0.0.1:8000 --name desktop --score 200
```

查看控制台 <http://127.0.0.1:8000/v0.3/console> ，填写 Admin Key，提交测试任务。

或使用 API：

```bash
curl -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" http://127.0.0.1:8000/v0.3/status
curl -X POST http://127.0.0.1:8000/v0.3/tasks \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"kind":"sum","payload":{"numbers":[1,2,3]},"required_cpu":1,"required_memory_mb":64}'
```

## 2. Docker Compose 本地多节点模拟

在仓库根目录建立 `.env`（已加入 .gitignore）：

```text
OPENCOMPUTE_ADMIN_KEY=填入独立的随机长密钥
OPENCOMPUTE_JOIN_KEY=填入另一个随机长密钥
```

然后：

```bash
docker compose --profile sim up --build --scale worker=3 -d
# 控制台: http://127.0.0.1:8000/v0.3/console
docker compose --profile sim logs -f worker
```

Docker 默认只向本机 `127.0.0.1` 暴露 API，模拟 Worker 通过 Docker 内部网络注册。`opencompute_data` 卷持久化 SQLite 数据。普通模拟 Worker 使用轻量镜像，不安装 PyTorch；现有 CPU 推理 API 仍使用 PyTorch 镜像。

## 3. 调度行为

1. 加入密钥 `X-Join-Key` 仅用于注册；服务端生成独立 Worker ID 和一次性返回的 `X-Node-Token`。
2. 每个 Worker 上报 CPU 核心数、总/可用内存、CPU 负载、能力列表、模拟/自测性能评分和最大并发槽位。
3. 管理员使用独立 `X-Admin-Key` 创建任务，设置最低 CPU 核心和可用内存要求。
4. Worker 请求领任务时，调度器在**所有在线且具备能力**的节点中，按性能评分和剩余资源选择优先节点；已占满槽位的节点不会继续领取任务。
5. SQLite `BEGIN IMMEDIATE` 保证多个 Worker 同时领取时同一任务不会被重复分配。
6. 任务使用带随机令牌的租约；节点失联或租约到期后重新排队。超过最大尝试次数进入失败状态；已过期令牌不能提交结果。

`compute_score` 由 Worker 自报，不是可信的统一基准。任务成功只表示 Worker 返回结果，目前**没有跨节点重复验证或抗作弊机制**。

## 4. 本地模拟与测试

```bash
python -m unittest discover -s tests -p 'test_cluster_v03.py' -v
python -m benchmarks.cluster_sim
```

模拟脚本注册高性能台式机、普通笔记本、低性能设备，让它们领取四个测试任务，并校验高分节点优先、忙碌时可以使用低分节点。它不会运行真正的多设备 LLM 前向计算。

## 5. 安全边界与下一步

- 当前只能在**本机、受信任的局域网或私有 VPN**进行实验。不要将管理/注册/节点通信接口直接开放公网。
- Join Key 会下发给受信任的 Worker，尚没有细粒度准入、密钥轮换、TLS 双向身份认证或设备签名。
- Worker 仅能执行明确允许、输入受上限约束的三种 CPU 任务，**不能执行用户任意代码**。
- 任务的 `required_memory_mb` 是保守调度请求，不是强制资源隔离；CPU 时间/进程隔离、恶意 Worker 识别、数据机密性和跨节点推理尚未实现。
- 接下来：把 v0.2 张量并行 Worker 与 v0.3 节点注册协议统一，增加节点预热/权重分发、跨设备网络测量、失联恢复及隔离运行。
