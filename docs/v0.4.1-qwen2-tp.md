# OpenCompute AI v0.4.1 — Qwen2 张量并行推理适配器

## 实际交付范围

OpenCompute AI 已有真正的 **CPU Gloo Qwen2 计算路径**：随机测试权重可以拆成 Rank 0 / Rank 1，在单机独立 Worker 中通过 Gloo 协作生成 Token。它不是仅在模型目录增加一行文字。

主要源文件：

- `compute/qwen2_shards.py`：受信任的本地 Qwen2/HF 风格 `state_dict` 分片，float32 CPU；保留完整 rank0 embedding/LM head。
- `compute/qwen2_core.py`：非交错式 RoPE、RMSNorm、分组查询注意力 GQA、SwiGLU、因果掩码、Rank 本地 KV Cache。
- `compute/qwen2_generate.py`：Gloo 广播/All-Reduce、逐 Token 贪心解码、各 Rank 的加载预检查和权重字节统计。
- `compute/qwen2_reference.py`：原始 Qwen2 张量的单进程参考实现。
- `cluster_v031/coordinator.py` / `worker.py` / `limits.py`：会话引擎字段持久化、节点 TP 能力匹配、固定引擎白名单、Worker 加载及进程限制。
- `cluster_v04/models.py` 和 `api.py`：`qwen2-synthetic` 与 `qwen2-local-checkpoint` 进入模型中心实验选项。
- `tests/test_qwen2_v041.py`：1 Rank / 2 Rank 输出和每步 logits 与参考实现数值对照、损坏分片失败、可信节点隔离与 API 调度。
- `benchmarks/qwen2_tp_session_demo.py`：完整本机 HTTP 服务 + 两个实际 Worker + Gloo + 参考结果对照。

**仍是实验版本。** 官方 DeepSeek / Qwen 完整权重尚未完成在本平台的实测验证，模型中心保留 `DeepSeek-R1-Distill-Qwen-1.5B` 为「待适配」，直到下载、可信导出、完整权重内存验证、数值兼容性测试都通过。该标记不能因为 Qwen2 算子跑通而提前改成已支持。

## 为什么优先 Qwen2

DeepSeek-R1-Distill-Qwen-1.5B 的公开配置采用 `Qwen2ForCausalLM`，`num_attention_heads=12`、`num_key_value_heads=2`，因此目前实现的两份 TP 分片方法在结构上适用（每 Rank 1 个 KV head、6 个 Query heads）。但这只是结构条件，不等于大型检查点的性能和内存要求已经满足。Llama 蒸馏模型、完整 DeepSeek MoE、量化模型不在此适配器范围。

当前实现刻意不支持自定义远程 Python 权重代码、非默认 RoPE scaling、滑动窗口注意力、量化权重以及 KV head 数不能被 Rank 数整除的模型。配置不兼容时会显式拒绝运行。

## 不下载任何大模型的本机验证

已安装项目开发依赖与 CPU PyTorch 后：

```bash
python -m compute.qwen2_shards --synthetic --workers 2 \
  --output ./.opencompute/qwen2-fixture
python -m torch.distributed.run --standalone --nproc-per-node=2 \
  -m compute.qwen2_generate \
  --shards ./.opencompute/qwen2-fixture \
  --prompt-ids 1,2,3 --max-new-tokens 3 --report-logits
python -m unittest discover -s tests -p 'test_qwen2_v041.py' -v
python -m benchmarks.qwen2_tp_session_demo
```

这些命令使用的是**随机参数合成模型**，返回 Token ID 没有自然语言语义。

模型中心本机地址：`http://127.0.0.1:8000/v0.4/console`。有两个已经注册的可信 `tp_qwen2` Worker 时，可选择「Qwen2 GQA 合成测试模型」并创建真正的 Rank 推理会话；选择「Qwen2 本地可信检查点」则要求管理员已在 `OPENCOMPUTE_TP_CHECKPOINTS` 目录中放置匹配格式的导出分片。接口拒绝选择 GPT-2 条目加载 Qwen2 分片，反之亦然。

## 面向真实 DeepSeek-R1-Distill-Qwen-1.5B 的尚未解决问题

1. **文件大小上限：** 当前每个分片/LM head 文件不超过 512,000,000 字节。Qwen2 1.5B 的完整词表 `rank0_io.pt` 在 float32 下可远超这一阈值，不能直接按现有默认限额接入。需要专门设计可验证的多文件分片、流式加载或安全提高资源配额。
2. **float32 内存：** 原始 BF16 权重导出为 float32，容易显著增加内存占用；还必须处理分片加载峰值和 Rank 0 词表内存瓶颈。
3. **真实数值兼容性：** 当前自动化一致性主要针对合成 Qwen2 权重，尚未针对 DeepSeek 官方发布检查点做全量输出、Tokenizer 与 BF16 精度测试。
4. **外部网络安全：** 仍是受信任本机 / Linux 环境的原型，不支持公众贡献算力的未知设备；需要 mTLS、租约吊销、身份和结果校验、真正的执行隔离。
5. **模型许可与来源：** 官方地址清晰不意味着任意第三方衍生权重安全。下载时应固定版本、审核使用许可和来源，再记录 SHA-256。
6. **其他模型：** Qwen2 不是 Llama、Qwen3 或 DeepSeek MoE 的通用计算引擎；须分别实现架构适配，不能直接运行不兼容检查点。
