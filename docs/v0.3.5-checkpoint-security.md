# OpenCompute AI v0.3.5 — 检查点安全与可审计的失败重建

**状态：** 代码、单元测试和 GitHub Actions 步骤已提交。本版本尚未获得独立的最新 CI 通过确认；v0.3.4 的两项 CI 已通过，不应混淆。

**范围：** 可信本机 CPU GPT-2 张量并行研究原型。本阶段未启动跨设备实验，不支持公网不可信节点，也不具备推理过程中断点续算。

## 为什么要做这一版

之前，模型文件的 SHA-256 索引在 Worker 首次查询时生成，并保存在协调器**内存**中。其问题是：会话的文件校验历史无法可靠随 SQLite 持久化；文件在检查点重试前发生替换时，缺少与原始会话绑定的、不可随意重新计算的比较依据。

v0.3.5 将模型文件的 `name` / `size` / `sha256` 固定写入 SQLite 表 `tp_files`，在会话创建期间与 Rank 分配一起提交事务。文件传输前比对磁盘实际摘要；从失败会话重建时，先验证所有原始文件是否与**旧会话登记的指纹**一致。不会因为文件被悄悄修改就更新预期摘要。

这确保的是 **一致性和意外篡改检测**，**不是** 对模型来源的加密认证。掌握 SQLite 和文件系统写权限的恶意管理员仍可能同时改写文件及校验表。

## 改动明细

| 部分 | v0.3.5 处理 | 边界 |
|---|---|---|
| `tp_files` 表 | 逐会话持久化固定文件名、大小和 SHA-256 | 旧会话没有指纹时，**拒绝重试**而非信任其当前内容 |
| `tp_sessions.retry_of` | 记录重试链上一次会话 ID | 新会话的推理仍从原始 Prompt 开始，KV Cache 不恢复 |
| 文件分发 | 节点仍只能获得它被分配的 Rank；通过打开的 `O_NOFOLLOW`（在支持的平台上）文件句柄复核摘要，并直接流式传输**同一个句柄** | 防止检查后“重开路径”的替换竞态，但无法阻止有写权限的本机进程在读取同一 inode 时修改其内容；仍需不可变存储 |
| 清单解析 | 验证维度、整除、激活函数、LayerNorm ε；限制 `manifest.json` 最大 16 KiB | 只能说明结构符合预期，不能证明权重内容合理 |
| 权重文件 | 每个文件最多 512 MB，拒绝符号链接，禁用任意模型 URL | Worker 仍只应加载由可信管理员预先导出的模型 |
| Worker 下载 | 拒绝异常大小、SHA-256 格式和额外文件；使用 `torch.load(weights_only=True)` 校验张量形状 | `weights_only` 不能防止内存耗尽，不能等同于执行沙箱 |
| 子进程权限 | 只传递有限的环境变量名单；不再继承管理员/云端密钥、`PYTHONPATH`、`LD_PRELOAD` | 完整运行环境与模型文件仍需要可信 |
| 缓存权限 | POSIX Worker 设置 `umask(077)` | 不是跨用户安全容器隔离 |
| 可选容器 | TP Worker 使用 UID/GID 10001；可选本机协调器也使用非 root 身份，保留 CPU/内存/PID 配额 | 默认旧版 Compose 未切换；仅适合 Linux 可信本机 |

### 数据库兼容与重建策略

首次加载新 `SessionCoordinator` 时：

1. 若旧数据库缺少 `retry_of`，添加可空字段；如果没有 `tp_files`，创建该表。
2. 服务重启时，原来进行中的 TP 进程组因失去内存中的 TCPStore，仍会被标记为 `failed`。
3. 新会话自动写入完整文件指纹。历史会话未预先固定指纹，**不能在 v0.3.5 中自动追认当前文件**。管理员应重新导出可信权重并建立新会话。
4. 对新版本失败的会话执行 `POST /v0.3.1/sessions/{id}/retry`，会检查原分片和清单是否保持不变，重新建立 Rank 组，并在新记录中持久化 `retry_of`。

本版本依然没有自动重试次数与指数退避、并不支持将已经生成的 Token 或 KV Cache 自动续接，也没有跨物理节点故障容错。

**升级建议：** 升级前备份 `.opencompute/cluster.sqlite` 或 Docker 中的 `/data/cluster.sqlite` 以及会话模型文件。不要直接删除旧数据文件。

## 安全测试与 CI

不需要购买云服务器或启动跨物理设备：

```bash
python -m unittest discover -s tests -p 'test_checkpoint_security_v035.py' -v
python -m unittest discover -s tests -p 'test_tp_v031.py' -v
python -m unittest discover -s tests -p 'test_rendezvous_v033.py' -v
```

新增测试覆盖：跨重启持久化、SHA-256 篡改检测、已打开文件句柄与路径替换竞态、重试来源持久化、篡改后拒绝重试、遗留数据迁移、分片符号链接拒绝、异常 JSON 清单、Worker 下载元数据校验与密钥环境隔离。

GitHub Actions 的 `v0.3 heterogeneous CPU cluster` 工作流已加入这些测试，还会运行现有的本机 HTTP + Gloo 集成演示。最新版 CI **必须单独确认绿色**。

## 下一阶段仍需解决

- 进一步使用内容寻址、只读且不可变的模型文件存储，防止拥有文件写入权限的本机进程在传输过程中改写同一 inode。当前已经避免校验后重新按路径打开文件，但仍不能防止有权限的进程修改已打开文件的内容。
- 为每个 TP 会话使用独立、可撤销的短期凭证，而不是只依赖长效 Node Token。
- 将用户和模型隔离到更完整的执行沙箱；验证 Docker 环境真实 CPU/RAM 配额生效。
- 未知节点的 mTLS / 私有网络、结果独立校验、成本与信誉机制。
- 更高效的模型切分，避免在普通家庭互联网环境下每个 Token 都进行大量 All-Reduce。

**结论：** v0.3.5 解决了“文件身份与失败重试难以审计”的重要一环，不表示已经具备可对外出租的安全共享算力池。
