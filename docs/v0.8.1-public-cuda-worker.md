# OpenCompute AI v0.8.1 — Public CUDA Worker

This milestone connects an admitted public CUDA Worker to the existing v0.7 GPU inventory and task scheduler. It does not create a second GPU task queue.

## What is connected

1. A public Worker completes the v0.8 challenge and joins with a short-lived admission proof.
2. A CUDA Worker receives a `public_gpu` node identity. Its token is stored as a hash in the cluster database and the public-pool database.
3. The identity is scoped: public GPU nodes may report GPU inventory, claim GPU tasks, renew GPU leases, and complete their own GPU leases. They are rejected by the trusted CPU Worker authentication path.
4. The Worker reports one CUDA-visible device (`cuda:0`) and refreshes GPU telemetry periodically.
5. It polls the existing `/v0.7/nodes/{node_id}/gpu-claim` endpoint, executes the bounded `matmul_checksum` allowlist, and submits results through the existing GPU completion endpoint.
6. Public `matmul_checksum` results are independently checked by the scheduler against a deterministic CPU checksum before they can be marked completed. Incorrect results are requeued or failed according to the task retry limit.

## Start a public CUDA Worker

Use a machine with an NVIDIA GPU, a working NVIDIA driver, and a CUDA-enabled PyTorch installation compatible with that driver. A CPU-only PyTorch build cannot join in CUDA mode.

Download the standalone Worker from:

`https://YOUR_OPENCOMPUTE_DOMAIN/v0.8/public/worker.py`

Then run:

```bash
python opencompute-worker.py --url https://YOUR_OPENCOMPUTE_DOMAIN --device cuda
```

The Worker requires HTTPS for non-localhost origins. It does not need an administrator key, join key, or manually entered node token. Keep the process running while contributing compute. Stop it with Ctrl+C.

The CPU verification mode remains available:

```bash
python opencompute-worker.py --url https://YOUR_OPENCOMPUTE_DOMAIN --device cpu
```

CPU-only public Workers do not receive GPU task permissions.

## Submit and inspect a GPU task

Only the administrator submits work. Do not put the administrator key in a Worker command or distribute it to contributors.

```bash
curl -X POST https://YOUR_OPENCOMPUTE_DOMAIN/v0.7/gpu-tasks \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"kind":"matmul_checksum","payload":{"size":256},"required_vram_mb":256}'
```

Inspect the GPU inventory and task queue with the existing authenticated endpoints:

- `GET /v0.7/gpus`
- `GET /v0.7/gpu-tasks`

Both require `X-Admin-Key`.

## Security and current limitations

- Public GPU node tokens are not administrator credentials and cannot authenticate to the trusted CPU Worker endpoints.
- Public workers can execute only the allowlisted GPU task. No uploaded Python, shell commands, or arbitrary user code is executed.
- GPU inventory is still Worker-reported telemetry, not cryptographic hardware attestation. The deterministic checksum verifies the returned task result, but it does not prove that the GPU hardware itself performed the computation.
- This milestone exposes one CUDA-visible device per Worker process. Multi-GPU reporting from one host, AMD ROCm/XPU public execution, Qwen2 model execution on public GPUs, and cross-device tensor/model sharding remain separate follow-up work.
- The first integration task is a bounded matrix checksum. It validates the public GPU execution path; it is not yet a production LLM inference service.
