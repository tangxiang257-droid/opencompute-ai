# OpenCompute AI v0.4.4 — Qwen2/DeepSeek-Qwen BF16 和可信离线数值验收

## 实施范围

本版继续复用多模型目录、Qwen2 Gloo 张量并行、v2 Safetensors 分片和可信本机 Worker，不修改公网接入政策。实现 **BF16 磁盘权重、可选且限定字节预算的 CPU FP32 缓存**，以及 **不自动下载官方模型的 Tokenizer/Hugging Face 对照入口**。

注意：本阶段测试使用随机合成权重。**尚未下载、分片、执行或验证 DeepSeek-R1-Distill-Qwen-1.5B 官方完整权重**，因此 DeepSeek 在模型中心仍应显示「待适配」。

## 1. BF16 Safetensors 数据格式

- `opencompute-qwen2-tp-v2` 保持原格式名，在 manifest 增加 `weight_dtype: "bfloat16"` 或 `"float32"`。历史 v2 manifest 不带此字段时视为 float32，v1/GPT-2 不变。
- 导出 Embedding 行块、LM Head 行块、每层每 Rank 的 Safetensors 文件，都允许选用 BF16 存储；模型元数据严格拒绝未知精度和文件头/配置不符。
- **计算依然是 CPU FP32**：每次读取 BF16 块后按需转换成 FP32，再进入现有 RoPE/RMSNorm/GQA/SwiGLU 和 Gloo All-Reduce 逻辑。KV Cache、激活张量也仍为 FP32。
- BF16 可能带来量化舍入差异。针对 BF16 已舍入的同一组测试权重，逐 Token Logits 与单机参考实现进行数值比较；不能拿“与原始 FP32 权重完全相同”作为通过标准。
- BF16 只明确减少磁盘权重文件字节数，不意味着模型推理 RSS、磁盘总开销或吞吐按比例变化；读取、转换以及会话复制仍有额外资源需求。

本地可信目录的导出示例：

```bash
python -m compute.qwen2_safetensors \
  --model-dir /local/trusted-qwen2 --workers 2 \
  --export-to /local/exported-qwen2-bf16 \
  --chunked --storage-dtype bfloat16
```

无需模型权重的容量估算：

```bash
python -m compute.qwen2_safetensors \
  --config /local/trusted-qwen2/config.json --workers 2 \
  --storage-dtype bfloat16
```

`--storage-dtype bfloat16` 与旧版非分块 v1 导出不能一起使用；会明确拒绝。校验单文件上游 Safetensors 可继续使用已核实的 `--expected-sha256`。多文件仍需分文件信任清单，不能据此断言文件来源已被证明。

## 2. 受预算限制的缓存

在 `compute.qwen2_chunked.TensorLRU` 提供可选的最近最少使用缓存：记录缓存中 **FP32 张量的可见字节数**，溢出预算就淘汰旧块；默认 **0 MiB（不缓存）**。支持 0–512 MiB 的独立 Layer 和词表 IO 缓存预算：

```bash
python -m torch.distributed.run --standalone --nproc-per-node=2 \
  -m compute.qwen2_generate \
  --shards /local/exported-qwen2-bf16 \
  --prompt-ids 1,2,3 --max-new-tokens 3 \
  --layer-cache-mib 64 --io-cache-mib 64
```

在受信任 Worker 的本地环境中，也可以设置 `OPENCOMPUTE_TP_LAYER_CACHE_MIB` 和 `OPENCOMPUTE_TP_IO_CACHE_MIB`；Worker 验证范围后将其传给固定 Qwen2 子进程。**服务器分配的任务不能任意修改这两个缓存额度**。

缓存预算只统计已缓存权重，不包括正在分配或复制的临时张量、进程运行时、KV Cache、激活、PyTorch 内存分配器和操作系统页缓存；两项缓存如果同时设为 512 MiB，Worker 可能额外使用约 1 GiB 权重缓存，实际运行需结合 Linux cgroups 与 RSS 监控谨慎选择。是否提速必须测量，尤其顺序扫描所有 Transformer 层与完整 LM Head 时，缓存命中不一定显著。

## 3. 可信离线 Tokenizer 和官方参考模型对照

新增 `benchmarks/qwen2_offline_reference.py`。它只接受管理员已经放在**本机**的 Qwen2/DeepSeek 模型目录，明确使用 `local_files_only=True`、`trust_remote_code=False`；权重导入保持 Safetensors-only，不自动联网下载，不打开不可信 pickle 权重。

先测试本地 Tokenizer：

```bash
# 仅在单独的可信验证虚拟环境中安装可选依赖
python -m pip install 'transformers>=4.44,<5' tokenizers

python -m benchmarks.qwen2_offline_reference \
  --model-dir /local/trusted-qwen2 \
  --text '你好，请介绍一下自己。' --tokenize-only
```

如果已经使用同一模型的可信本地权重导出了双 Rank v2 分片，可以只运行 TP 并解码结果：

```bash
python -m benchmarks.qwen2_offline_reference \
  --model-dir /local/trusted-qwen2 \
  --shards /local/exported-qwen2-bf16 \
  --text '你好，请介绍一下自己。' \
  --max-new-tokens 2
```

最后，只有在可信本机具有**足够内存**时，才显式加上 `--compare-hf` 启用官方架构的完整 CPU FP32 Hugging Face 参考模型：

```bash
python -m benchmarks.qwen2_offline_reference \
  --model-dir /local/trusted-qwen2 \
  --shards /local/exported-qwen2-bf16 \
  --text '你好，请介绍一下自己。' --max-new-tokens 2 \
  --compare-hf
```

此方式将比普通多 Rank 分片推理消耗**多得多的 RAM**，且可能很慢，不属于默认 CI、不是免费云端服务，也未在本轮以 DeepSeek 官方权重实际执行。验证逐 Token 贪心 Token ID 和 Logits 张量形状、最大绝对误差及 `allclose`（容差可通过 `--atol` 和 `--rtol` 设置）；不通过时明确返回错误。

参考模型使用可信本地 Safetensors、`Qwen2ForCausalLM` 和 FP32 全量模型。因 BF16 存储会引入离散舍入误差，设置合适容差非常重要；单个模型与提示词通过，也不能证明所有输入都一致。

官方 DeepSeek 蒸馏模型来源与配置（请固定具体版本、检查许可和 SHA）：

- https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B
- https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B/blob/main/config.json

## 4. 测试和当前边界

```bash
python -m unittest discover -s tests -p 'test_qwen2_bf16_v044.py' -v
python -m unittest discover -s tests -p 'test_qwen2_chunked_v043.py' -v
```

新测试使用随机生成的 Qwen2 参数、1 Rank 与 2 Rank Gloo：检验 BF16 文件确实更小、BF16 张量头部、舍入后 FP32 参考结果、非法精度拒绝、缓存命中和内存计数、现有安全导入和离线 Tokenizer 调用限制。不会触发大型模型下载或 Hugging Face 全模型加载。

尚需开展的独立验收：

1. 在可信机器对官方 **DeepSeek-R1-Distill-Qwen-1.5B** 的指定 revision 固定完整权重/Tokenizer 哈希并校验模型许可；
2. 检查真实模型的每一层数值与全模型逐 Token Logits，记录 BF16/FP32 的实际误差分布；
3. 测量逐层读取导致的磁盘流量、峰值 RSS、首次 Token 延迟及后续 Token/s，确定 LRU 是否值得开启；
4. 如需支持外部个人设备，先建立公网接入所需的身份认证、可信执行隔离、传输加密、结果校验与失联恢复。

**CI 必须以最新提交的 GitHub Actions 具体测试结论为准**。当前仍然是受信任本机 CPU 原型，不是正式上线的网站，也不应宣称 DeepSeek 官方权重已经验证通过。
