# Windows 本地启动指南（v0.6）

本项目提供 PowerShell 启动器，目标是让 Windows 用户不必手工编辑环境变量或记忆多条 Docker 命令。当前仍然是本机/可信网络研究环境，不是公网多租户服务。

## 先决条件

1. Windows 10/11。
2. 安装 Docker Desktop，并等待 Docker Engine 显示 Running。
3. 首次启动需要网络连接，以下载基础镜像和安装 Python/PyTorch 依赖。
4. 从 GitHub 克隆仓库：

       git clone https://github.com/tangxiang257-droid/opencompute-ai.git
       cd opencompute-ai

## 一键启动 API

在仓库根目录打开 PowerShell：

       powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1

启动器会检查 Docker CLI/Engine、首次生成两组不同的 256-bit 随机密钥并写入根目录 .env（不会覆盖已有 .env）、验证 Compose 配置、构建并启动 API、等待 /health 就绪、输出网站地址和管理员密钥，并自动打开浏览器。

访问 http://127.0.0.1:8000/，在页面顶部粘贴启动器输出的管理员密钥。

## 一键启动三个模拟 CPU Worker

       powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -SimulateWorkers

该命令会使用 Compose 的 sim profile 启动 API 和三个普通 CPU Worker，并等待节点注册。Worker 只执行白名单任务：sum、sha256、matmul_checksum。这用于验证注册、心跳、任务领取和结果回传，不代表模型分片推理已跨设备运行。

## 状态、日志和停止

查看容器、API 健康状态和最近日志：

       powershell -ExecutionPolicy Bypass -File .\scripts\status-local.ps1

停止服务（保留持久化数据卷）：

       powershell -ExecutionPolicy Bypass -File .\scripts\stop-local.ps1

也可以查看 Worker 日志：

       docker compose --profile sim logs --tail 80 worker

## 密钥和数据安全

- .env 已被 .gitignore 排除；不要把管理员密钥、加入密钥或节点令牌发给他人。
- 启动器不会覆盖已有 .env，也不会自动删除数据库或 Docker 数据卷。
- 若 .env 里仍是示例占位符，启动器会停止并要求先更换为两组独立随机密钥。
- 默认服务端口只绑定 127.0.0.1:8000。不要通过路由器端口映射或公网反向代理直接暴露该 HTTP 服务。
- -SimulateWorkers 创建的是 Docker 容器内的模拟节点；它们共享同一台物理主机 CPU，不能用于证明跨主机网络加速或显存聚合。

## 常见问题

**Docker Desktop 未启动：** 打开 Docker Desktop，等待 Engine Running 后重试。

**端口 8000 已占用：** 先检查是否已有旧的 OpenCompute 容器或其他本机服务。不要直接删除数据卷。

**Worker 少于 3 台：** 运行 .\scripts\status-local.ps1 并查看 docker compose --profile sim logs --tail 80 worker。容器首次启动时可能需要数秒下载/安装完成后才注册。

**PowerShell 阻止脚本：** 使用本指南中的 powershell -ExecutionPolicy Bypass -File ... 形式运行；该参数只对这次启动命令生效，不会永久修改系统执行策略。
