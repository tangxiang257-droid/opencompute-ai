# OpenCompute AI v0.4.9 — 有界请求队列与公平调度原语

## 本阶段交付

新增 `compute/request_queue_v049.py`，提供独立于模型后端和网络传输的动态请求准入队列：

- **全局队列上限**：默认最多 128 个等待调度的请求，超限立即返回 `QueueFullError`，避免无界内存增长。
- **客户端配额**：默认每个 client 最多 16 个等待请求，防止单一客户端占满队列。
- **公平调度**：客户端之间采用 Round-Robin；同一客户端内部 FIFO。持续有请求的客户端不会因另一个客户端的突发流量而长期饥饿。
- **请求截止时间**：使用 monotonic deadline；排队超时的请求会在派发前被清理，并向等待方返回 TimeoutError。
- **请求生命周期**：唯一 ID 在排队和执行期间均不可重复；消费者必须通过 complete/fail 完成请求。
- **安全关闭**：关闭后拒绝新请求，清理并失败所有尚未派发的请求；已在执行中的请求可由消费者完成。
- **等待超时隔离**：调用方等待结果超时不会取消共享 Future，避免一个客户端的等待取消误杀正在执行的工作。

## 当前接口示例

```python
import asyncio
from compute.request_queue_v049 import FairRequestQueue

async def main():
    queue = FairRequestQueue(max_pending=128, max_pending_per_client=16)
    ticket = await queue.put(
        request_id="req-001",
        client_id="user-001",
        payload={"model": "qwen2", "prompt": [1, 2, 3]},
        timeout=30,
    )

    async def worker():
        request = await queue.get()
        try:
            # 下一阶段在这里接入真实 PP 推理执行器
            result = {"request_id": request.request_id, "status": "completed"}
            await queue.complete(request, result)
        except Exception as exc:
            await queue.fail(request, exc)

    task = asyncio.create_task(worker())
    result = await ticket.result(timeout=35)
    await task
    await queue.close()
    print(result)

asyncio.run(main())
```

## 验收

`tests/test_request_queue_v049.py` 覆盖轮询公平性、客户端 FIFO、全局/单客户端限额、重复 ID、排队过期、过期请求清理、工作失败传播、关闭行为和非法输入。

本版本先交付并验证调度原语，**尚未将其接入 v0.4.8 的双 Rank Gloo 推理进程、FastAPI 服务或网站控制台**；也没有实现多执行器并发上限、流式 Token、真实网络取消或跨设备容错。不得将“队列公平性测试通过”描述成模型服务已支持动态多用户请求。

下一步应在独立适配层将队列消费者接入推理会话管理，明确每个 PP 组的并发容量、排队/执行超时和客户端身份来源，再运行端到端负载测试。
