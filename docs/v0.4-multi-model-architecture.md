# OpenCompute AI v0.4 — 多模型算力平台架构（第一阶段）

## 产品决策

**DeepSeek 是首批目标模型，不是唯一模型。** OpenCompute AI 的平台层必须与模型品牌、参数规模和推理实现解耦。

```text
用户 / 模型中心
    ↓ 选择模型 ID + 执行模式
模型目录 ModelRegistry（名称、家族、架构、适配状态、官方来源）
    ↓ 严格检查 ModelSpec / 支持能力
推理路由 ModelRouter（仅允许代码中已注册的引擎）
    ├── GPT-2 Tensor Parallel 引擎 ✅ 已存在，实验环境
    ├── Qwen2 / DeepSeek-Qwen 蒸馏引擎 ⏳ 待开发
    ├── Llama / DeepSeek-Llama 蒸馏引擎 ⏳ 待开发
    ├── DeepSeek-V3 / R1 MoE Expert Parallel ⏳ 研究阶段
    └── 外部 OpenAI 兼容 API 接入 ⏳ 待开发（不使用个人算力池）
    ↓
设备调度 / 资源预留 / 身份校验 / 文件指纹 / Gloo 等实际执行层
```

## 代码入口

- `cluster_v04/models.py`: 统一、显式的模型清单，包含 `id`、`family`、`architecture`、`engine`、`capability`、`modes`、可信来源与是否需要本地检查点。新增模型时原则上添加模型声明并提供对应引擎适配器；绝不依靠用户输入执行任意 Python 模块。
- `cluster_v04/api.py`: `GET /v0.4/models` 和 `GET /v0.4/models/{model_id}` 提供目录查询；`POST /v0.4/sessions` 以管理员密钥保护，并严格把已支持的模型映射到现有协调器。
- `cluster_v04/console.html`: `http://127.0.0.1:8000/v0.4/console`，能搜索、按家族/状态筛选模型；暂不支持的模型只展示状态，不允许启动。
- `tests/test_model_registry_v04.py`: 验证未知模型拒绝、未实现引擎拒绝、管理员鉴权、GPT-2 实验模型路由、检查点参数不被随意覆盖。

### 如实区分三种状态

| 状态 | 在目录可见 | 可启动 |
| --- | --- | --- |
| `experimental` | 是 | **对应引擎已实现**，但仍需相应数量的可信在线 Worker |
| `planned` | 是 | 否：需要模型架构和推理后端实现、正确性测试及许可证审核 |
| `research` | 是 | 否：大型 MoE/专家并行等研究目标 |

注意：`experimental` **只表示代码路径已具备**，不等于已经部署了节点、安装了权重或获得外网可用性。目录也不自动下载模型、占用硬盘或启动服务。

## 当前真正能启动什么？

目前仅有：
1. `gpt2-synthetic`：随机权重 GPT-2 结构，仅用于验证 TP 流程，没有实际语言能力。
2. `gpt2-local-checkpoint`：管理员事先安全导出并放到本地可信检查点目录的 GPT-2，运行时依赖已注册且满足资源要求的 `tp_gpt2` 节点。

DeepSeek-R1-Distill-Qwen-1.5B、Qwen2.5-0.5B-Instruct、DeepSeek-R1-Distill-Llama-8B 等目前仅在目录中标为 **planned**。DeepSeek-R1 完整 MoE 为 **research**。这几个型号**尚未被 OpenCompute AI 实际运行**。

## API 举例（可信本机）

```bash
# 查看模型目录（无需管理员密钥，仅静态元数据）
curl http://127.0.0.1:8000/v0.4/models

# 查询具体适配状态
curl http://127.0.0.1:8000/v0.4/models/deepseek-r1-distill-qwen-1.5b

# 已实现的 GPT-2 合成结构：需先有足够 TP Worker
curl -X POST http://127.0.0.1:8000/v0.4/sessions \
  -H 'Content-Type: application/json' \
  -H "X-Admin-Key: $OPENCOMPUTE_ADMIN_KEY" \
  -d '{"model_id":"gpt2-synthetic","mode":"tensor_parallel","workers":2,"prompt_ids":[1,2,3],"max_new_tokens":3}'

# 选择计划中的 DeepSeek 模型将明确返回 HTTP 409，不会假装运行
```

## 真正扩展到多模型时的开发顺序

1. 保留并稳定现有 GPT-2 张量并行引擎作为数值正确性和通信基准。
2. 实现 Qwen2 结构适配（RoPE、RMSNorm、GQA、SwiGLU）及经过授权的 Safetensors 权重映射，以较小的 Qwen2.5 模型与 DeepSeek-R1-Distill-Qwen-1.5B 做一致性测试。
3. 实现 Llama 系列的独立配置/权重适配，审核模型许可；不能因为“DeepSeek 蒸馏”四字就使用 Qwen 适配器加载 Llama 权重。
4. 增加模型感知的显存/内存估算，以及 TP、流水线、请求级任务分发的候选策略。
5. 为完整 DeepSeek MoE 研究专家路由/专家并行、跨节点通信与实际成本。
6. 对第三方 API 采用独立的安全连接器，不把它包装成“使用共享算力池推理”。

## 安全和权利边界

- 官方来源链接只代表开发者公开的模型资源位置，**不表示模型文件无风险**。必须保持 SHA-256、可信文件来源审查和文件解析限制。
- 不直接安装远程自定义代码，不使用用户提供的可执行文件路径作为引擎入口。
- 不默认下载大模型，不允许用户提交任意远程 URL 后直接执行。
- 不同模型采用不同许可，商业可用性需逐项确认；不能对所有模型统一假定已获商业授权。
- 个人设备的调度与第三方 API 服务分别计费、区分执行地点和隐私政策。
- 当前仍是可信本机研究环境；不支持公网陌生节点以及跨物理设备的安全接入。
