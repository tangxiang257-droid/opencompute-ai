# OpenCompute AI v0.4.1 — Qwen2 通用张量并行适配（阶段一）

本版本为原有 GPT-2 引擎新增一个**实际的 Qwen2 数学与 Gloo CPU 张量并行原型**。它为后续兼容 Qwen2.5 与 DeepSeek-R1-Distill-Qwen 提供架构基础，但**尚未证明可以运行完整官方 0.5B/1.5B 权重**。

## 本次已经实现的计算部分

- HF Qwen2 标准权重结构的离线分片导出，使用独立 `rank_N.pt` 与 `rank0_io.pt`；
- RMSNorm、非交错 rotate-half RoPE、因果掩码、GQA、SwiGLU；
- Attention 输出与 MLP 输出的跨 Rank All-Reduce；
- 各 Rank 分离 KV Cache，贪婪解码与显式输入校验；
- rank 0 负责 embedding 与语言模型 head；Gloo 通信仍局限可信本机；
- 旧 GPT-2 运行引擎与 API 保持独立；
- 多模型目录中的 `qwen2-synthetic` 只作为**实验用随机权重**模型可启动；官方预训练 DeepSeek/Qwen 条目暂仍标为 `planned`。

### 可重复的可信本机合成测试

```bash
python -m compute.qwen2_shards --synthetic --workers 2 --output .opencompute/qwen-synthetic
python -m torch.distributed.run --standalone --nproc-per-node=2 \
  -m compute.qwen2_generate --shards .opencompute/qwen-synthetic \
  --prompt-ids 1,2,3 --max-new-tokens 3 --report-logits
```

独立参考实现 `compute/qwen2_reference.py` 使用原始 HF 风格的完整权重，测试检查 1/2 Rank 输出与参考数值的一致性、损坏 Rank 分片拒绝运行，以及模型目录/Worker 能力调度规则。

### 模型架构与支持规模（重要限制）

| 目标模型 | HF 架构 | 官方配置关键特征 | 当前推理状态 |
|---|---|---|---|
| Qwen2.5-0.5B-Instruct | Qwen2 | 14 query heads、2 KV heads、24 层、896 hidden、tie embedding | 仅结构适配，真实权重尚未验收 |
| DeepSeek-R1-Distill-Qwen-1.5B | Qwen2 | 12 query heads、2 KV heads、28 层、1536 hidden、untied LM head | 仅结构适配，真实权重尚未验收 |
| DeepSeek-R1-Distill-Llama-8B | Llama | 非 Qwen2 | 需要独立适配器 |
| DeepSeek-R1 完整 MoE | DeepSeek-V3 类 MoE | 专家架构 | 仅研究计划 |

当前导出器仅支持 float32 CPU 研究路径，并且要求 **query heads、KV heads、MLP intermediate 均能被 Rank 数整除**。上述两个 Qwen2 模型有 2 个 KV heads，因此**现版本至多能配置 2 个 Rank**，并不能在 4 个 Worker 上执行它们的 TP。真实权重很大，rank 0 的完整 embedding/LM head 会超出当前每文件 512 MB 的安全限额。对于 untied LM head 的 DeepSeek 1.5B，rank 0 尤其容易形成内存瓶颈。

后续需要增加 BF16/量化权重存储、rank0 embedding/输出头分片、独立的 Safetensors 数据加载与可信度校验、适配器精确数值测试和大型模型内存规划。**不能为了让测试通过而直接放宽模型文件大小限制**。

### 安全与部署边界

- CLI 的 `--model` 只接受管理员已缓存的本地模型，`local_files_only=True`、`trust_remote_code=False`；来源和许可证需用户自行核查。
- 合成模型只检验计算路径，不会输出有意义的自然语言。
- 没有真实家庭网络、云服务器、预训练权重验证、跨主机 Gloo 性能或公网身份安全。
- SHA-256 校验仅检验分片传输完整性，不等于可信模型或可信计算证明。
- 所有新增 Qwen2 单元测试及本机多 Rank 测试依赖 GitHub Actions 的当前绿色状态作为验收；代码提交本身不代表 CI 成功。
