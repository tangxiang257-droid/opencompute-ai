## Composition

Its C-purpose table has a permanent owner/task key, so changing C node/session/nonce does not create a second slot in that authority. `await CReceivingPolicy.create(adapter, resource_id=..., charge=..., parent=..., maintenance=...)` uses that exact confirmed registration and independent receiving/maintenance permissions. It retains the actual USER and local revocation gate; no wire receipt or B permission replaces these. Its one-time claim shares the existing local receiver claim fence, so local/remote receiving modes cannot both consume one live consent. Cross-database copies/rollback and hostile in-process modification are not protected globally.

`ReceivingStore.for_authority(issuer)` uses the SAME issuer DB; C owns a different fresh ReceivingStore with a persistent incarnation. ReceivingController requires the exact CReceivingPolicy and its issuer-backed store. ReceivingRole requires a configured exact issuer node/certificate and its own identity, receiving, maintenance and resource providers. Missing providers reject before work. Wire fields bind purpose, full task/source/plan/model, confirmed C terms, B placement/config declaration digest, issuer incarnation, existing resource ID and charge. Central challenge and C persistent incarnation are tied to the original authenticated control connection. A reconstructed channel/store/reply cannot be used as a live handle. The envelope stage=1 is a B-result routing label, never a C execution stage.

Reopened stores deny all live writes, including retirement changes. Unknown state therefore requires trusted later investigation, not blind retry or automatic release.

Eighteen protocol tests exercise memory control exchanges, default deny, input-adapter boundary, maintenance, lost ACK/commit, cleanup, original issuer, persisted factory consumption and ingress failure. Another test_runtime exercises actual RuntimeConsent mapping: input-ready requires current install permission AND parent permission, not execute authorization. These are separate integration seams, not one complete newly authorized cross-process GPU/publication acceptance test. No actual OS process split, TLS handshake, genuine user/issuer/capacity service, CUDA completion or physical-stop validation occurred.
